Home Lab Infrastructure

個人基礎設施與資安實驗環境

用於 Linux 服務、網路架構、裝置通訊、遠端管理、服務恢復與安全邊界實驗的個人基礎設施環境。

為什麼開始做

需要建立一個可重複實驗的環境，用來理解 Linux 主機與服務部署、IoT 裝置回報、MQTT 訊息流程、路由器與子網路設定、遠端存取、固定 IP、網路切換後的連線問題、服務中斷與恢復、裝置離線，以及敏感資料與非敏感通知的分離。

系統簡介

此環境使用 Raspberry Pi 與既有路由器建立，主要用於個人學習與專案驗證。它與 SecureCare 等醫療原型保持邏輯與環境分離，網路架構、服務監控與復原方式仍在逐步整理。

我的角色

Architecture planning, Linux configuration, network configuration, service deployment, device integration, remote access exploration, monitoring, troubleshooting, and documentation

系統層級

裝置 網路 基礎設施 服務 通訊 安全 監控

系統簡介

用於 Linux 服務、網路架構、裝置通訊、遠端管理、服務恢復與安全邊界實驗的個人基礎設施環境。

使用的系統、程式語言與裝置

Raspberry Pi / Applied Linux / Applied Docker / Applied MQTT / Experimenting Node-RED / Experimenting OpenWrt / Applied Tailscale / Exploring WireGuard / Exploring SSH / Applied XRDP / Applied Router configuration / Applied

初步構想

  • 建立穩定的 Linux 實驗主機
  • 部署 Docker services
  • 建立 MQTT Broker
  • 整合 Node-RED
  • 接收 ESP32 或其他裝置訊息
  • 理解 OpenWrt 網路設定
  • 建立固定 IP 與服務定位
  • 探索較安全的遠端存取
  • 記錄故障與修復流程
  • 規劃非敏感 Telegram 通知

非目標

  • 不作為企業級基礎設施
  • 不承諾 24/7 可用性
  • 不存放正式醫療資料
  • 不公開暴露所有內部服務
  • 不將 Telegram 作為敏感資料傳輸管道
  • 不宣稱完成完整零信任架構
  • 不宣稱企業級備援
  • 不宣稱已完成正式資安稽核

現在遇到的問題

外部網路無法連回 Home Lab

系統簡介
在外部環境無法直接連回 Home Lab。
排查
檢查網路位置、遠端存取方式與路由假設。
處理方式
探索透過 Tailscale 或 WireGuard 類型方式建立 private remote access。
目前驗證
進行中
學到的內容
遠端存取必須同時考慮復原能力與暴露面控制。

OpenWrt GUI 無法連線

系統簡介
修改路由器設定後，管理介面無法正常連線。
排查
檢查網路介面、IP 與 LAN 設定。
處理方式
先恢復可管理狀態，再繼續調整設定。
目前驗證
部分完成
學到的內容
修改網路設定前必須保留復原路徑。

SSH host key changed

系統簡介
重新安裝或更換裝置後，SSH 顯示 host key mismatch。
排查
先確認裝置身分，再修改本機 SSH 記錄。
處理方式
確認後移除舊 known_hosts 記錄並重新連線。
目前驗證
已應用
學到的內容
不可在未確認主機身分時直接忽略 host key 警告。

Node-RED 初次部署問題

系統簡介
首次部署 flows.json 或服務時未如預期生效。
排查
檢查服務狀態、流程檔案位置與重新部署方式。
處理方式
調整部署流程並記錄問題。
目前驗證
部分完成
學到的內容
自動化流程需要部署紀錄，不只是視覺化 flow 設計。

裝置離線或無法重新連線

系統簡介
網路切換、服務中斷或重新啟動後，裝置可能停止回報。
排查
檢視 reconnect、buffering 與 retry 行為。
處理方式
規劃重連與可能的訊息暫存機制。
目前驗證
需要更多測試
學到的內容
裝置曾經連線成功，不等於系統具備可靠性。

路由器設定造成網路中斷

系統簡介
調整 OpenWrt、ASUS 或 Xiaomi router 拓撲時可能造成連線中斷。
排查
檢查拓撲、管理 IP 與復原步驟。
處理方式
在後續修改前先記錄拓撲與回復步驟。
目前驗證
部分完成
學到的內容
路由器、主機、容器與裝置問題需要分層排查。

已有解決方案

Raspberry Pi

原因
低成本、低功耗，適合長時間執行 Linux 實驗。
取捨
效能與資源比完整伺服器有限。

Docker

原因
分離服務並提高部署可重複性。
取捨
增加容器網路與儲存設定複雜度。

MQTT

原因
適合裝置遙測與狀態回報的輕量通訊。
取捨
需要處理身分驗證、存取控制與重連機制。

Node-RED

原因
能快速串接裝置訊息、自動化與通知。
取捨
Flow 需要文件化，憑證也需要控管。

OpenWrt

原因
提供較高的網路設定可見度與控制能力。
取捨
設定錯誤可能造成網路失聯。

Private Remote Access

原因
降低內部服務直接公開的風險。
取捨
需要額外處理身分、路由與復原規劃。

Telegram Notification

原因
將非敏感系統摘要傳送到手機。
取捨
敏感資料必須留在本地，訊息內容要最小化。

限制

  • 目前是個人學習實驗環境。
  • 不具備企業級備援。
  • 不承諾持續可用性。
  • 監控與告警仍在逐步建立。
  • 網路拓撲仍可能調整。
  • 遠端存取方案仍在比較或測試。
  • 部分舊路由器可能停止取得安全更新。
  • 金鑰與憑證管理仍需深化。
  • 尚未完成完整網路分區驗證。
  • 尚未完成正式弱點掃描與滲透測試。
  • 裝置離線補送機制尚未完整實作。
  • Telegram 通知仍為規劃或初期實作。
  • 不處理正式醫療或敏感資料。

學到的內容

  • 網路修改前必須先設計恢復路徑。
  • 固定 IP、服務名稱與拓撲文件能降低除錯成本。
  • 裝置連線成功不代表服務具備可靠性。
  • 遠端存取必須同時考慮安全與可恢復性。
  • 路由器、主機、容器與裝置問題需要分層排查。
  • 敏感資料與通知摘要需要分開處理。
  • Home Lab 的價值不只是運行服務，而是記錄失敗與修復方式。
  • 自動化流程同樣需要權限與憑證管理。

研究觀點

研究 / 工程問題
如何在低成本個人環境中，建立可重複、可觀察、可恢復且具基本安全邊界的裝置與服務實驗平台？

子問題

  • 如何安全地從外部管理內部服務？
  • 如何降低路由設定錯誤造成的失聯風險？
  • 如何讓裝置在中斷後重新連線或補送資料？
  • 如何區分敏感資料與可外送的狀態摘要？
  • 如何記錄服務與裝置的健康狀態？
  • 如何用有限硬體設計可重複的教學環境？
